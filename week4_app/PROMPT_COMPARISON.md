# 요청 A/B 비교 기록

## 현재 상태: 미검증

이 과제 작업에서는 기능을 구현하는 단일 대화만 진행했다. 같은 조건의 별도 요청 A와 B를 실제로 실행해 두 응답을 관찰하지 않았으므로 응답 차이, 품질 차이, 선택 이유를 결과인 것처럼 작성하지 않는다. 현재 사용 모델의 식별자도 실행 메타데이터에서 확인할 수 없어 미검증이다. 코드와 테스트 결과는 A/B 모델 비교의 대체 근거가 아니다.

| 항목 | 요청 A | 요청 B |
|---|---|---|
| 프롬프트 | 미실행 | 미실행 |
| 실행 시각 | 미검증 | 미검증 |
| 사용 모델 | 미검증 | 미검증 |
| 응답 원문/결과 | 미수집 | 미수집 |
| 로딩·성공·실패·재시도·중복 입력 기준의 관측 차이 | 미검증 | 미검증 |
| 선택 이유 | 실제 응답 비교 후 기록 | 실제 응답 비교 후 기록 |

## 재현 가능한 비교 요청 초안

두 프롬프트를 별도 요청으로 각각 실행하고, 같은 저장소 상태·도구 권한·테스트 기준을 적용한다. 실제 모델명, 요청 시각, 응답 원문(또는 핵심 차이를 확인할 수 있는 인용), 실행한 검사와 종료 코드를 기록해야 한다.

- **요청 A:** `lib/main2.dart`에 모의 공지 앱을 구현해줘. 로딩·성공·실패 상태를 구분하고 실패 화면에서 다시 시도할 수 있게 해줘. 진행 중 중복 탭으로 요청이 중복되지 않는지 요청 횟수도 표시해줘.
- **요청 B:** `lib/main2.dart`에 외부 패키지/API 없이 Future 기반 모의 공지 앱을 구현해줘. AC1 최초 로딩 표시, AC2 응답 검증 후 성공 목록, AC3 실패 안내와 재시도, AC4 재시도 로딩과 복구, AC5 로딩 중 중복 탭에도 요청 1회만 발생을 위젯 테스트로 검증해줘. await 전후 상태, 예외 처리, 응답 검증의 한계도 설명해줘.

두 응답을 실제로 확보한 뒤 공통 조건, 관측한 차이, 채택한 응답/아이디어와 선택 이유를 이 문서에 보충한다.
